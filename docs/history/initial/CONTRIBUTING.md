## 1. Our Core Invariants (The Guardrails)
Before submitting a proposal or a pull request, verify that your changes align with these non-negotiable architectural principles:

*   **Radical Transparency:** The protocol must remain 100% open source. We reject any data models, proprietary software layers, or analytics tracking that operate under "shadow" or secret environments.
*   **The Firewall of Agency:** We build tools to optimize and stabilize background macro-mechanics (logistics, resource distribution, environmental homeostasis). We strictly reject any contributions designed to optimize, monitor, or manipulate human consciousness, belief systems, or cultural choices.
*   **Cognitive Friction over Viral Growth:** For Pillar II (SPI), we prioritize algorithms and data standards that introduce deliberate processing friction to de-escalate high-conflict, instinct-based human cascades. We penalize any systems design that prioritizes unconditional behavioral engagement over systemic stability.

## 2. How to Interact with the Ecosystem

We organize collaboration into two distinct channels depending on the nature of your input:

### A. Conceptual, Philosophical, and Economic Debates
If you want to discuss the ethics of endosymbiosis, expand upon Bertaux's philosophy, or brainstorm the space-frontier economic dynamics:
1. Navigate to the **Discussions** tab of this repository.
2. Search existing threads to avoid redundancy.
3. Open a new thread under the appropriate category (e.g., `Philosophy`, `Macro-Economics`, or `General`).

### B. Technical Specifications and Code Modules
If you are optimizing mathematical optimization formulas, building Python schemas for data ingestion pipelines, or writing automated API tests for the S-Score:
1. **Open an Issue:** Describe the specific mathematical vulnerability or pipeline optimization you want to address. Wait for alignment in the comments.
2. **Fork the Repository:** Create your own branch to work on the adjustments.
3. **Submit a Pull Request (PR):** Target your PR to the `main` branch. Ensure your commit messages are concise and your code includes clear markdown documentation.
